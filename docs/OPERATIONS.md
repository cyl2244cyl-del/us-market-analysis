# 운영 구조

## 로컬과 GitHub의 역할

예약 실행은 기존 로컬 프로젝트에서 계속 수행하고, 비공개 GitHub 저장소 `cyl2244cyl-del/us-market-analysis`는 정돈된 프로젝트·리포트 공간으로 사용합니다.

| 자료 | 로컬 | GitHub |
| --- | --- | --- |
| 자동화 코드와 설정 | 실제 실행본 | 검증된 버전 보관 |
| 일일·실적 Markdown | 생성·검증 | 읽기 좋은 프로젝트 구조로 누적 |
| 실적 상태와 출처 | 자동화 작업 상태 | 검증된 상태 보관 |
| SQLite·백업 | 운영 원본 | 업로드하지 않음 |
| 차트·HTML 산출물 | 생성 및 검증 | Markdown 표시용 차트 7개와 완성 HTML만 보관 |

GitHub 반영에 실패해도 로컬 자동화와 검증된 로컬 결과는 그대로 유지합니다. 다음 실행에서 다시 동기화할 수 있도록 GitHub 실패를 로컬 실패와 분리합니다.

## 실적 문서 흐름

실적 시즌 인덱스는 `reports/earnings/<season>/README.md`, 종목별 문서는 `reports/earnings/<season>/<TICKER>.md`에 저장합니다.

종목별 문서는 회사·분기당 하나만 사용하며 다음 단계를 같은 문서에 누적합니다.

1. `scheduled`: 일정만 확인됨
2. `preview_ready`: 발표 전 핵심 질문과 판단 기준 준비
3. `release_captured`: 공식 발표 수치 반영
4. `call_reviewed`: 콘퍼런스콜 답변과 변화 반영
5. `regular_close_recorded`: 다음 정규장 반응과 투자 논리 변화 반영
6. `five_day_reviewed`: 5거래일 뒤 반응과 최종 회고 반영

9개 종목 모두 회사별 질문이 들어간 상세 문서를 미리 생성합니다. 시즌 인덱스에서 전체 문서를 연결하고, 프리뷰·공식 결과·콜·주가 반응을 기존 문서에 누적합니다.

## 출처와 쓰기 규칙

- 회사 IR, SEC 공시, 주주서한, 발표자료와 공식 콜을 우선합니다.
- 회사 발표, 시장 컨센서스, 외부 해석, 자동화 판단을 구분합니다.
- 신뢰할 수 있는 비교치가 없으면 beat/miss를 만들지 않습니다.
- 자동화는 기존에 확인된 출처와 발표 전 질문을 보존합니다.
- GitHub에는 검증된 변경 경로만 반영하며 DB, 백업, 인증정보는 올리지 않습니다.

## 예약 실행

- 실적 문서: 화~토 07:30 KST
  - 48시간 이내 발표 종목은 프리뷰를 준비합니다.
  - 새 발표가 있으면 수치와 공식 자료를 반영합니다.
  - 이미 발표된 종목은 콜과 다음 정규장 반응이 완성될 때까지 다시 확인합니다.
- 일일 리포트: 화~토 09:00 KST
  - 이전 미국 거래일 자료를 수집하고 검증 후 GitHub에 동기화합니다.
  - 검증된 HTML에 내장된 차트 7개를 그대로 PNG로 추출합니다.
  - 날짜별 Markdown에서 차트를 바로 표시하고, 이미지를 누르면 원본 크기로 엽니다.
  - 해당 날짜의 Markdown·차트 7개·HTML과 인덱스를 한 원격 커밋으로 반영합니다.

## 로컬 호환성

기존 `일일리포트/`, `실적리포트/`, 루트 SQLite와 자동화 경로는 그대로 유지합니다. 새 Markdown 실적 문서는 GitHub 게시용 출력으로 추가하며, 기존 HTML 트래커는 당분간 로컬 호환 출력으로 유지합니다. 로컬 파일 이동이나 삭제는 새 자동화의 무인 GitHub 동기화가 검증되기 전에는 수행하지 않습니다.
